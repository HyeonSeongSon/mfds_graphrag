# mfds-graphrag 전체 4주 플랜

## Context

`wiki/projects/local-graphrag-mfds-weekly-plan-20261023.md`의 8주 플랜을 사용자 요청(2026-10-26)으로 **4주로 압축**한다. 부록(1주차 상세)은 1주차 D4에 잠그는 PREREG의 원본이라 이 4주 일정 기준으로 함께 확정한다. 전제: 주 5일 전업, 사람 작업은 낮에 하고 GPU · API 배치는 밤에 돌린다. 이 문서에서 "사람 검수"는 사용자가 하는 작업이다.

## 범위: 8주 → 4주

| | 유지 | 제외(스트레치 또는 설계만) |
|---|---|---|
| 데이터 | 법령 · 고시 · 처분 · DUR 정형 적재, 판례 · 해석례 · 심판 API 추출 | 법령 연혁(시점 질의), 첨부파일 고시(식품공전) |
| 평가 | PREREG 잠금. dev 150 / test 850 / 거절 세트 150, Text2Cypher test 450 | 로컬 4B 추출 기준선(어댑터 A용이었음) |
| 모델 | 4B 베이스, 8B 기준선, 벤더 API 천장, **어댑터 B(Text2Cypher)** | 어댑터 A · 합성 사내 문서, 비교군 모델(Kanana · Mi:dm · Gemma) |
| 서빙 | llama.cpp + 런타임 어댑터, 양자화 표, 오프라인 기동 증거 | 증분 갱신 · 접근 권한 분리(README에 설계만), 동시 4 이상 부하 |

핵심 성과 3개와 각각의 사전 등록 지표(정의는 부록 4절):
1. **파인튜닝 4B vs 파인튜닝 없는 8B:** Text2Cypher test 450의 실행 정확도(사전 등록 보조 비교). 학습한 의도와 held-out 의도 수치를 나란히 보고하고, 헤드라인에는 "학습한 의도 기준"인지 밝힌다. 채택 판정은 베이스 4B 대비로 따로 한다
2. **그래프 vs 벡터 vs 하이브리드:** 유형별 정답 근거 hit@5(조문 단위). 질의 경로(Cypher) 없이 각 방식이 낸 순수 순위 목록으로 잰다. 경로를 포함한 전체 파이프라인은 "시스템" 행으로 따로 보고한다. 특히 T4 다단계 200
3. **GPU 6GB 한 장으로 API 품질의 몇 %:** 답변 주 지표(정답 근거 인용률, 인용 상한 5)의 로컬 ÷ API 비율과 부트스트랩 신뢰구간, 양자화 수준별 VRAM · 속도 표

3주차 D5 실행은 D5 밤 안에 끝나도록 잡았다. 4주차 D1 부하 측정과 겹치면 부하 측정을 오후로 미룬다. 임베딩(bge-m3)은 CPU, 벤더 API 실행은 GPU와 병렬로 돌린다.

**벤더 API(토큰 추정):** 1주차 D3에 문서 길이로 추정하고 사용자가 예산 상한을 정한다. 2주차 D1에 표본 100건으로 실제 비용을 재서, 상한을 넘을 것 같으면 추출 입력을 판결요지 우선으로 줄인다.

## 2. 스키마 v0.1

ID 규칙 예: `law:001234`, `art:001234:44`, `art:001234:7-2`(제7조의2), `par:001234:44:1`, `item:001234:44:1:3`.

**성분 · DurRule ID(모델이 답변에 그대로 옮겨 적을 수 있게 읽을 수 있는 형태로):**
- 성분: `ing:<정규화한 영문명>`(고시 별표의 성분명은 영문, 1주차 D1 확인). 정규화는 소문자화 · 공백 · 전각 문자 정리. 괄호 안 제형(`(경구제)` 등)은 DurRule 조건 속성으로, 동의어(`valproic acid(valproate)`)는 `aliases`로, 분류번호는 속성으로 분리한다. 복합제(`A + B`) · `~ 함유제제` 처리 규칙은 D2에서 정한다. 염 형태("~염산염" 등)는 염을 뗀 이름을 `aliases`에 넣어 검색 매칭에만 쓰고, 노드는 고시 표기 단위로 둔다(같은 성분의 다른 염이 고시에 따로 있으면 따로 노드). 규칙은 `mfds/ingredients.py`에 두고 테스트와 함께 잠근다
- DurRule: 별표 1 `dur:pair:<성분명 A>:<성분명 B>`(두 이름 정렬), 별표 2 `dur:age:<성분명>:<연령 조건>`, 별표 3 `dur:preg:<성분명>`. 성분명은 `ing:`를 뗀 정규화 대표명이고, 이름 안의 `:`는 `_`로 바꾼다. 같은 ID가 여러 행에서 나오면(제형 · 내용이 다른 행) 행 내용 해시 순서로 `#2` · `#3`을 붙인다. 행 내용이 같으면 스냅숏이 바뀌어도 ID가 같다. 단, 같은 쌍의 행이 늘거나 줄면 `#` 번호가 밀릴 수 있다(이번 4주는 스냅숏 하나라 문제없음, 한계로 기록)

## 4. 평가 사전 등록 (`eval/PREREG.md`)

원칙: 정답은 원자료에서 가져온다. 생성기는 Neo4j를 읽지 않는다. 생성 · 분할 시드는 PREREG에 고정한다. "근거 ID"는 조문 · 항 · 별표 · DurRule의 정규 ID를 말한다.

### 4-1. 크기 기준
- **시스템 간 비교:** 짝 비교(McNemar, α 0.05, 검정력 80%, 불일치 20% 가정)에서 10%p 검출에 155개, 5%p에 626개. 목표 검출 차이는 10%p. T2 검색 비교(양성 150)는 155보다 조금 작아 검정력이 약 79%다
- **양자화 간 비교:** 대부분 같은 답을 내므로 불일치를 5%로 가정한다. 차이의 95% 신뢰구간 반폭은 dev Text2Cypher 70문항 ±5.2%p, dev 150 ±3.6%p, Text2Cypher test 450 ±2.1%p, test 850 ±1.5%p. 그래서 dev로는 느슨하게 거르고, 판정은 test에서 비열등성으로 한다(4-5)

### 4-2. 검색 · 답변 평가셋

| 유형 | 입력 → 정답 | 정답 출처 | dev | test |
|---|---|---|---|---|
| T1 처분 → 조항 | 위반 내용(날짜 · 차수 제거) → 조문(+항) | 식품 처분 근거 조항 필드 | 30 | 200(조항별 상한) |
| T2 DUR | 성분 쌍 → 병용금기 판정 + 근거 DurRule | 병용금기 고시 별표 | 30 | 200(양성 150 / 음성 50) |
| T3 판례 → 조문 | 판결요지 → 참조조문 | 판례 참조조문 필드 | 30 | 200 |
| T4 다단계 | 아래 하위 유형 | 아래 | 30 | 200 |
| T6 집계 | 개수 질문 → 숫자 | 원자료 집계(제외 목록 적용, 4-4) | 10 | 50 |
| T5 답변 불가 | 타 부처 법령 · 없는 조문 · 범위 밖 | 생성 규칙 | 20 | 거절 세트 150(따로 보고) |

- **T2:** 정답 단위는 고시 별표가 아니라 개별 DurRule이다(별표 하나만 찾아와도 적중하는 문제 방지). 음성 문항은 판정 정확도로만 채점하고 hit@5 · 인용률 계산에서 뺀다. 그래서 T2 검색 비교는 양성 150문항 기준이다
- **T1 · T3 표본 부족 시 대체 규칙(사전 등록):** 표본 가능 문항이 460건 미만이면 묶음 상한을 50 → 100 순으로 올린다. **단, 올렸을 때 제외 목록이 전체 처분(T1) 또는 판례(T3)의 30%를 넘으면 상한을 올리지 않고 바로 test를 줄인다.** 그래도 모자라면 dev 30을 먼저 확보하고 test를 (표본 가능 문항 − 30) ÷ 2로 줄인다(200 상한). 이 처리는 늦게 온 출처(예: 식품안전나라 키가 잠금 뒤 도착)에도 그대로 적용하고, 2주차 D4 동결 전에 AMENDMENTS에 기록한다. test가 155 미만이 되면 10%p 검출이 안 된다는 점을 한계로 적는다
- **T1 · T3 표본 조건:** 정확 일치 묶음과 그 근접 중복 이웃(4-4)을 합친 크기가 **50건 이하**인 문항만 뽑는다. 문항을 뽑으면 이 전체가 그래프에서 빠지기 때문이다. 흔한 위반이 빠지는 쪽으로 치우친다는 점은 한계로 기록한다
- **T1 해석:** 비슷한 과거 처분이 그래프에 없으므로, T1은 조문 내용만 보고 근거 조항을 맞히는 과제다. "유사 처분 검색" 능력은 재지 않는다

T4 하위 유형(단순 조회는 제외. T2 · T4 · T6 슬롯은 정답이 비지 않고 정답 결과가 200행 이하인 것만 뽑는다. Text2Cypher 실행 결과 제한이 200행이기 때문이다):
| 하위 유형 | 예 | 정답 출처 | test |
|---|---|---|---|
| M1 위임 추적 | 약사법 제N조가 위임한 시행령 조문 | 3단비교(파서와 독립) | 60 |
| M2 원천 → 조항 → 위임 | 판례 X의 참조조문을 위임받은 시행령 조문 | 참조조문 · 처분 필드 + 3단비교 | 60 |
| M3 DUR 교차 | 성분 X와 병용금기이면서 임부금기인 성분 | 고시 별표 집합 연산. 검색 · 인용 정답은 두 조건을 이루는 DurRule 집합, 성분 집합은 Text2Cypher 결과 일치와 답변 정확도로 채점 | 50 |
| M4 인용 역추적 | 약사법 제N조를 인용하는 조문 | `refs.py`와 독립적인 넓은 후보를 사용자가 거름(아래) | 30 |

- **M4 정답이 비는 경우:** 대상은 예비 포함 36개를 시드 순서로 뽑는다. 두 평가셋은 같은 36개 풀에서 서로 다른 조건으로 30개씩 채운다
  - 검색 · 답변 T4: 2주차 D2에 시드 순서대로 검수해 **진짜 인용이 1개 이상인** 30개(검수 약 3시간). 정답이 사용자 검수에서 오므로 그래프 `CITES`가 비어도 문항은 유지한다(그 경우가 재야 할 그래프의 실패다)
  - Text2Cypher T4: 1주차 D5 적재 직후 정답 템플릿 결과(`CITES` 기반)가 **비지 않는** 30개를 시드 순서로 고른다
  - 어느 쪽이든 예비가 다 떨어지면 M4 test를 그 수만큼 줄이고 AMENDMENTS에 기록한다. 기록은 2주차 D4 동결 전에 끝낸다
- **M3 염 형태:** 1주차 D3 DUR 대조 때 "염을 뗀 별칭은 같은데 uid가 다른 성분"이 별표 사이에 몇 건인지 센다. 별표 3 성분의 5% 이상이면 M3 집합 연산을 염 제거 별칭 단위로 하고, 5% 미만이면 uid 단위로 하고 한계로 기록한다. 결과와 선택은 1주차 D4 dry-run 보고에 넣고 잠금 전에 확정한다
- **M4 정답 후보:** `refs.py`를 쓰지 않는다. 대상 조문 번호의 표현("제N조", "법 제N조", "같은 법 제N조", 약칭 + "제N조"; "제N조의2" 같은 다른 조문은 정규식 경계로 제외)을 같은 법 · 하위 법령 · 고시 본문에서 문자열로 검색한 결과 전체를 후보로 두고, 사용자가 진짜 인용만 남긴다. 그 결과와 `refs.py` 결과를 대조해 정규화기가 놓친 인용 수(재현율)와 잘못 잡은 인용 수를 기록한다
- **T4 분기(1주차 D1 결과로 결정):** 3단비교에 조문 단위 위임이 없으면 M1 · M2는 원문 위임 문구 파싱 + 전수 수작업 검증 각 30으로 줄인다. T4 test는 140이 되고, 10%p 검출이 안 된다는 점(약 12%p 수준)을 한계로 기록한다
- dev(150, 약 25분/회): 프롬프트 조정, 양자화 1차 선별. test(850): 채택 판정과 최종 보고에만 쓴다
- 라벨 검수: T1 · T3 자동 정답을 50개씩 사용자가 검수해 오류율을 기록한다. 오류율보다 작은 차이는 주장하지 않는다. 오류율에 따른 분기(2주차 D5 기준선 전에 끝냄):
  - 5% 이하: 그대로 진행하고 기록
  - 5% 초과 15% 이하: 오류 패턴을 고치는 규칙을 AMENDMENTS에 남기고 그 유형의 정답을 다시 생성한 뒤, 새 표본 50으로 다시 검수. **규칙 수정으로 문항 구성이 바뀌면** `exclusion_ids.json`을 다시 만들고 평가용 그래프를 2주차 D4 동결 전에 다시 적재한다
  - 15% 초과: 그 유형은 핵심 성과 2의 헤드라인에서 빼고 보조로만 보고

### 4-3. Text2Cypher 평가셋
- **출처:** T2 test 200 + T4 test 200 + T6 test 50 = **450**, 그리고 `NO_QUERY` 판정용 거절 세트 150. T1 · T3는 의미 검색 과제라 제외한다. dev는 T2 · T4 · T6 dev 70
- 각 문항은 의도와 슬롯 값을 메타데이터로 갖는다. 평가용 의도의 정답 Cypher 템플릿은 1주차에 잠근다(`schema/eval_cypher/`)
- **M4 문항은 검색 · 답변 T4와 다를 수 있다:** Text2Cypher는 그래프 정답 결과가 비지 않는 문항, 검색 · 답변은 사용자 검수 정답이 있는 문항으로 채우므로 같은 36개 풀에서 최대 6개까지 다를 수 있다(4-2)
- **T2 템플릿은 두 성분 uid와 판정값, 해당 DurRule ID를 함께 돌려준다.** 그래서 성분을 못 찾은 쿼리(uid가 null)와 "금기 아님" 판정이 구별되고, 빈 결과만 내는 쿼리는 음성 문항에서도 오답이 된다
- **결과 일치 규칙:** 정규 ID 집합이 같으면 정답(순서 무시, 순서를 묻는 의도는 만들지 않음). 숫자는 정확히 같아야 정답. T2는 (uid, uid, 판정, DurRule 집합)이 모두 같아야 정답. 부분 일치(Jaccard)는 보조로만 보고한다
- **주 지표:** 정답 Cypher 템플릿을 같은 그래프에서 실행한 결과와 일치하는 비율. 쿼리 능력만 분리해서 잰다
- **보조 지표:** 원자료 정답과 일치하는 비율(그래프 오류까지 포함한 종단 정확도). 그리고 그래프 천장(정답 Cypher 결과 vs 원자료 정답)
- **held-out 의도:** 평가용 의도 중 20%(2~3개)를 시드로 골라 `intents.yaml`에 표시하고 잠근다. 학습 데이터에서 제외한다. 보고는 학습한 의도 / held-out 의도로 나눠 나란히 둔다. held-out 문항 수가 155개 미만이면 기술 통계로만 보고한다

### 4-4. 누수 방지
- **묶음(분할 · 표본 단위):** T1은 정규화한 위반 문구(날짜 · 차수 · 공백 · 문장부호 제거)가 **정확히 같은** 처분끼리, T3는 사건번호가 같은 판례끼리 묶는다. Jaccard로 묶음을 잇지 않는다(A~B, B~C가 연쇄로 큰 묶음이 되는 문제 방지)
- **근접 중복 제외(별 모양 검사):** dev · test 문항 각각에 대해, 문자 5-gram Jaccard 0.8 이상인 다른 처분(T1) · 판결요지(T3)를 찾아 제외 목록에 더한다. 문항을 중심으로 한 번만 비교하고 연쇄하지 않는다. dev 문항이 test 문항과 0.8 이상이면 그 dev 문항을 버리고 같은 시드 순서의 다음 후보를 뽑아 수를 유지한다. 비교는 약 260 × 9천(T1), 약 260 × 1.6천(T3) 쌍이라 전수 비교로 충분하다
- **`eval/exclusion_ids.json`:** dev · test 원천의 묶음 전체 + 근접 중복, **T2(성분 쌍) · T4 · T6(집계 조건) dev · test 슬롯 조합**, **거절 세트에 쓴 타 부처 법령명 · 없는 조문 번호**, 평가 문항 문자열
- **스냅숏 고정:** `build_evalset.py`와 적재기는 같은 `data/raw/YYYYMMDD` 경로를 인자로 받는다. 그 날짜와 manifest 해시를 PREREG 잠금 기록(AMENDMENTS)에 넣는다. 늦게 온 출처(예: 식품안전나라)는 같은 스냅숏 디렉터리에 추가하고 manifest 해시를 다시 기록한 뒤, 해당 유형(T1 · T6)만 잠긴 코드 · 시드로 다시 생성한다. 이 작업은 2주차 D4 그래프 동결 전에만 허용한다
  - **적재기**가 읽어서 T1 · T3 묶음을 평가용 그래프와 벡터 인덱스에 넣지 않는다(검색기마다 따로 거르지 않고 적재 단계에서 뺀다). 시연용 전체 그래프는 4주차 D3 밤에 `--mode full`로 다시 적재한다
  - T2 · T4는 지식 자체를 묻는 문제라 제외하지 않는다. 단, T4 슬롯은 T1 · T3 제외 노드에서 뽑지 않는다
  - **T6 정답도 제외 목록을 적용한 원자료로 센다.** 그래야 평가용 그래프와 같은 기준이 된다. 제외된 노드 수(유형 · 묶음 크기 분포 포함)는 평가셋 데이터 카드에 기록한다
  - **학습 데이터 생성기**는 이 목록과 겹치면 중단한다. 평가 문항과 근접 중복(문자 5-gram Jaccard 0.8 이상)인 학습 문장은 버린다
- 의료기기법 계열 문항에는 `heldout_law` 태그를 붙이고 학습에서 제외한다. 문항 수는 생성 직후 기록한다
- 현행 법령에 없는 조문을 가리키는 과거 처분은 제외하고 건수를 보고한다

### 4-5. 지표와 채택 기준 (수치는 1주차 D4에 사용자 확인 후 잠금)
- **검색(2주차 동결 기준선):** 질의 경로 없이 각 방식의 순수 순위 목록으로 잰다. **순위 목록은 조문 단위로 바꾼다:** 항 · 호는 상위 조문으로, 별표 청크는 별표 ID로 바꾸고 중복을 지운 뒤 상위 5개를 자른다. DurRule은 그대로 둔다. 정답도 같은 단위로 바꾼다. 유형별 hit@5(정답 근거 ID 중 하나라도 상위 5에 있으면 적중, T2는 양성만), 보조로 recall@5. 경로를 포함한 전체 파이프라인은 "시스템" 행으로 함께 보고한다. "그래프가 낫다"는 유형별 McNemar p < 0.05일 때만 주장하고, 전체 평균만으로 헤드라인을 쓰지 않는다. T6은 검색 지표 없이 답변 숫자 정확도로만 본다
- **그래프 동결:** Text2Cypher 주 지표의 정답은 2주차 D4 저녁에 동결한 평가용 그래프에서 실행한 결과다. 동결본 덤프와 정답 결과 파일 해시를 AMENDMENTS에 기록한다. 동결 뒤 그래프가 바뀌면 베이스 4B · 8B를 다시 돌린다
- **서브그래프 파일:** 답변 비교의 입력은 문항별 서브그래프 파일(해시 기록)이다
  - 2주차 기준선의 4B · 8B · API 답변, 3주차 양자화 답변 비교: 2주차 기본 검색 방식(2주차 D4 dev로 정하고 동결 때 기록)이 만든 같은 파일. 양자화 효과와 검색 차이가 섞이지 않는다
  - 핵심 성과 3: 4주차 D3 최종 파이프라인(운영점 양자화 + 어댑터 B Cypher)이 만든 파일을 로컬 · API에 똑같이 넣는다
- **답변 주 지표: 정답 근거 인용률.** 답변이 인용한 근거 ID 중 **앞에서 5개까지만** 채점하고, 그 안에 정답이 하나라도 있으면 적중이다. 대상은 T1 · T3 · T4와 T2 양성(M3는 DurRule 집합 기준)
  - 채점 단위는 조문이다. 정답이 항일 때 같은 조문을 인용하면 적중으로 본다. 항까지 일치하는지는 보조로 보고한다
  - 보조 지표: 인용 정밀도(앞 5개 중 정답 비율), 근거 없는 주장 비율(서브그래프에 없는 ID 인용), T2 음성 판정 정확도, T6 숫자 정확도, 거절 세트 거절 정확도, test 오거절률
- **API 대비 비율(핵심 성과 3):** 로컬 주 지표 ÷ API 주 지표. 같은 문항 · 같은 서브그래프 · 같은 프롬프트(인용 상한 지시 포함)를 쓰고, 문항 단위 짝 부트스트랩 95% 신뢰구간(시드 고정, 1만 회)으로 보고한다. 인용 정밀도도 함께 둔다
- **어댑터 B 채택(3주차):** 2주차 D2에 만든 같은 기준 Q4 파일 위에서, Text2Cypher 주 지표(450 전체)가 베이스 4B few-shot 대비 +10%p 이상이고 McNemar p < 0.05. heldout_law와 held-out 의도는 문항 수가 155개 미만이면 기술 통계로만 보고한다
- **8B 보조 비교(핵심 성과 1):** 같은 450문항에서 어댑터 B 4B vs 8B few-shot, McNemar. 4B는 직접 만든 imatrix 없는 Q4_K_M, 8B는 공식 Q4_K_M이다. 공식 파일이 imatrix를 썼다면 양자화 방식 차이를 한계로 함께 적는다. p < 0.05로 4B가 높을 때만 "8B보다 낫다"고 쓴다. 아니면 차이와 95% 신뢰구간을 그대로 보고한다. 학습한 의도 / held-out 의도를 나란히 둔다
- **양자화 운영점(3주차):** 답변 지표는 베이스로 2주차 서브그래프 파일에서, Text2Cypher 지표는 어댑터 B를 얹은 상태로 동결 그래프에서 잰다. Q8은 기준점이며 CPU 오프로드를 허용한다. 병합 비교용 Q4는 기준 Q4와 같은 Q4_K_M(imatrix 없음)이다
  - 후보 자격: 컨텍스트 8k · KV q8에서 **전 층 GPU 적재(VRAM 6GB 이내)**
  - dev 선별: 자격이 있고, Q8 대비 답변 주 지표와 Text2Cypher 주 지표 하락이 모두 5%p 이내인 것 중 작은 순서로 2개
  - test 판정(비열등성): (후보 − Q8) 짝 차이의 95% 신뢰구간 하한이 답변 주 지표는 −2%p, Text2Cypher 주 지표는 −3%p보다 위. Text2Cypher는 450문항이라 차이가 0이어도 하한이 약 −2.1%p가 되므로 −2%p로는 판정할 수 없어 −3%p로 둔다
  - 통과한 후보 중 더 작은 쪽을 운영점으로 한다. 하나도 통과하지 못하면 자격이 있는 것 중 가장 큰 양자화를 운영점으로 하고, Q8 대비 차이를 그대로 보고한다

### 4-6. 추론 설정 고정
- **모델(2026-10-27 확정):** `Qwen/Qwen3-4B`(Apache 2.0, 파인튜닝 대상)와 `Qwen/Qwen3-8B`(공식 GGUF Q4_K_M, imatrix 없음, 6GB에서 GPU 26/37층). Qwen3.5는 Turing에서 fp16 QLoRA가 안 돼 제외(`docs/bakeoff-rule.md`). 정확한 저장소 이름 · 라이선스는 1주차 D1에 확인하고 PREREG에 적는다. 착수 시점에 새 세대가 있으면 같은 세대 짝으로 바꾼다
- **thinking 끔:** 모든 구성에서 chat template의 `enable_thinking=False`로 끄고, 출력에 `<think>`가 없는지 확인한다
- **llama.cpp 빌드:** 평가에 쓰는 빌드 번호를 AMENDMENTS에 기록하고, 4주차 Docker 이미지도 같은 빌드로 맞춘다(빌드마다 인자 형식 · 결과가 조금씩 다를 수 있음)
- **few-shot:** 답변 프롬프트는 모든 구성이 같다. Text2Cypher는 베이스 4B와 8B에 few-shot 6개, **어댑터 B는 학습 형식 그대로(few-shot 없음)** 쓴다

모든 구성(4B · 8B · 양자화 수준 · 어댑터 유무)에서 컨텍스트 8k, **KV 캐시 q8**(8k에서 약 0.56GB), temperature 0을 쓴다. VRAM이 모자란 구성(8B, 4B Q8)은 일부 층을 CPU로 내리고, 속도는 따로 보고한다. 도메인 imatrix 보정 텍스트는 법령 · 고시 본문만 쓰고, 평가 문항 문장과 평가 원천(제외 목록) 텍스트는 넣지 않는다.

## 5. 파인튜닝 데이터 설계 (`docs/finetune-data.md`, 2주차 D4 저녁 잠금, 생성은 3주차 D1~D2)

어댑터 B(Text2Cypher)만 다룬다. 어댑터 A는 4주 범위 밖이다.
1. `intents.yaml`의 학습용 의도(held-out 제외)마다 Cypher 템플릿을 만든다. 평가용 의도는 잠긴 정답 템플릿을 그대로 쓴다
2. 그래프에서 슬롯 값을 층화 추출한다(제외 목록 · heldout_law 제외, 정답이 비지 않는 슬롯 위주, T2형 음성은 일부만)
3. 의도마다 기본 문장 2~3개를 직접 쓴다. 평가 문항 문장과는 따로 작성한다. 바꿔 쓰기 5~10개(소비자 말투 · 약칭 · 오타)를 추가한다
4. 정답 Cypher는 템플릿이라 구조상 정답이다. 실행은 스키마 유효성 확인용이다. 바꿔 쓴 질문의 뜻이 달라지는 위험은 슬롯 보존 검사와 사용자 표본 100 검수로 막는다
5. 답변 불가는 `NO_QUERY`로 학습한다. **학습용 `NO_QUERY` 틀은 `schema/eval_questions/`의 거절 틀과 따로 작성**하고, 거절 세트에 쓴 타 부처 법령명 · 없는 조문 번호(제외 목록)는 쓰지 않는다
6. 평가 문항과 근접 중복은 제거한다(4-4). 학습 내부 검증 split은 이 데이터에서 따로 뗀다
- 규모: 약 5천 건. 데이터 카드: 원천 → 생성 → 필터별 탈락 → 최종 건수, 교사 모델 · 버전, 프롬프트 해시, 검수 결과
- 교사 모델: 1주차 D1 약관 확인 결과로 정한다. 금지면 오픈 가중치 모델이나 템플릿만 쓰고, 그 차이를 한계로 기록한다

# 부록 B: 2주차 상세 (비정형 추출 · MVP · 기준선)

구현 세부(프롬프트 문구, top-k, 홉 수, 점수 결합 상수)는 dev로 조정할 수 있다. 동결 기록은 두 번이다. 2주차 D4 저녁(첫 test 실행 전)에 그래프 · 채점 코드 · Text2Cypher 프롬프트, D5 오전에 파이프라인 설정(`configs/pipeline.yaml`) · 질의 경로 분류 프롬프트 · 답변 프롬프트의 해시를 AMENDMENTS에 기록한다. PREREG의 지표 · 문항 · 판정 기준은 바꾸지 않는다.

## B1. 비정형 추출 (D1~D2)
- **입력:** 판례는 판시사항 + 판결요지, 없으면 본문 앞 6천 자. **참조조문 필드는 항상 입력에서 뺀다**(정확도를 이 필드로 재기 때문). 해석례는 질의요지 · 회답 · 이유, 행정심판은 주문 · 청구취지 · 이유 앞부분(필드명은 1주차 고정 자료로 확인). 비용 측정 결과에 따라 전문 입력으로 넓힐 수 있다
- **출력 JSON:** `{doc_id, cited_refs: [원문 인용 문자열], issues: [쟁점 문구 3개 이하], conclusion_type: 인용|기각|각하|해석|기타, applied_laws: [법령명]}`
- **LLM은 조문 ID를 만들지 않는다.** 원문에 있는 인용 문자열만 뽑고, ID 변환은 `refs.py`가 한다(ID를 지어내는 문제 방지)
- **검증:** JSON 스키마, `cited_refs` 각 문자열이 입력에 그대로 있는지(없으면 버림), `refs.py` 해석 성공률. 참조조문 필드가 있는 문서로 조문 단위 정밀도 · 재현율 측정. 해석례 · 심판은 정답 필드가 없으므로, 2주차 D1 인용 파싱 표본 중 약 30으로 ID 변환이 맞는지만 확인한다. **해석례 · 심판 추출의 재현율은 재지 않는다**(한계로 기록)
- **적재:** 필드가 있는 문서는 `REFERENCES {source: 'field'}`, **추출 결과는 필드가 없는 문서에만** `REFERENCES {source: 'extracted'}`로 넣는다. `INTERPRETS` · `APPLIES` 추가. 추출 결과 파일과 해시 보관

## B2. 검색 3종 (D3)
모든 방식은 "근거 ID 순위 목록"(조문 · 항 · 별표 · DurRule)을 낸다. hit@5는 이 목록으로 잰다.

| 방식 | 동작 |
|---|---|
| 벡터 | bge-m3 벡터 인덱스에서 근거 노드 텍스트(조문 · 항, 별표는 1천 자 청크, DurRule 문장)를 질문과 비교해 상위 20 |

| 하이브리드 | 벡터 목록과 그래프 목록을 RRF(k=60)로 결합 |

- **조문 단위 변환:** 세 방식 모두 순위 목록을 조문 단위로 바꾼 뒤(항 · 호 → 상위 조문, 별표 청크 → 별표 ID, 중복 제거) 상위 5개를 자른다(PREREG 4-5)
- **질의 경로(파이프라인에만 적용):** 4B가 질문을 `{route: cypher | search | refuse, intent}` JSON으로 분류(llama.cpp JSON 스키마 제약). cypher 경로는 Text2Cypher 결과의 근거 ID를 목록 맨 앞에 두고 나머지를 기본 검색으로 채운다. **핵심 성과 2의 검색 비교에는 쓰지 않고**, 답변용 서브그래프 파일과 "시스템" 행에만 쓴다
- **기본 검색 방식:** 2주차 D4 dev 결과로 정한다(예상: 하이브리드)

## B3. 서브그래프와 답변 (D3)
- **서브그래프:** 근거 상위 5개 본문 + 각 노드의 1홉 이웃(상위 · 하위 위임 조문, 근거 고시) 요약, 최대 약 3천 토큰. 형식은 `[근거 ID] 제목: 본문` 줄 목록. 문항별 JSON 파일로 저장 · 해시
- **답변 출력(JSON 스키마 강제):** `{answer, citations: [근거 ID 최대 5], verdict: 금기|해당없음|null, number: 정수|null, refuse: bool}`. 로컬은 llama.cpp `json_schema`, API는 구조화 출력
- **시스템 프롬프트 요지:** 주어진 근거만 사용, 주장마다 근거 ID 인용, 인용은 5개까지, 근거가 부족하면 `refuse: true`
- **인용 검증:** 서브그래프에 없는 ID는 "근거 없는 주장"으로 집계

## B4. Text2Cypher 기준선 (D3~D4)
- **프롬프트:** 스키마 요약(라벨 · 관계 · 주요 속성) + few-shot 6개 + 질문 → Cypher 또는 `NO_QUERY`. **few-shot 예시는 학습용 의도에서만** 고른다(평가 문항 · held-out 의도 제외). 어댑터 B는 few-shot 없이 학습 형식 그대로
- **실행:** 읽기 전용 트랜잭션, 시간 제한 5초, 결과 200행 제한(정답이 200행 이하인 슬롯만 뽑으므로 정답이 잘리지 않음). 문법 오류 · 시간 초과는 오답
- **채점:** `eval/score_cypher.py`가 PREREG 4-3 규칙으로 비교

## B5. 실행 · 채점 도구
- `eval/run.py --config <yaml> --split dev|test|refusal`: 문항별 결과(jsonl) · 시간 · 토큰 수 기록, 이어서 실행 가능
- `eval/score.py`: hit@5 · recall@5 · 인용률 · 정밀도 · 판정 정확도 · 숫자 정확도
- `eval/stats.py`: McNemar(불일치 25 미만은 정확 이항), 짝 부트스트랩(시드 고정 1만 회)
- **llama.cpp 공통 설정:** 컨텍스트 8192, K · V 캐시 q8_0, flash attention 켬, temperature 0, thinking 끔(chat template 인자). 인자 형식(예: `-fa on`)은 고정한 빌드에 맞춘다. 4B는 전 층 GPU, 8B는 VRAM에 맞춰 GPU 층 수를 정하고 값을 기록. V 캐시 양자화에 flash attention이 필요하므로 Turing 동작을 1주차 D1에 확인
- **해시 기록:** 채점 도구는 PREREG 규칙의 구현이므로, 2주차 D4 저녁 동결(첫 test 실행 전) 때 그래프 · Text2Cypher 프롬프트와 함께 해시를 AMENDMENTS에 기록한다. 파이프라인 설정 · 질의 경로 분류 프롬프트 · 답변 프롬프트는 D5 오전에 기록한다

## B6. 데모 화면 (D4)
Streamlit 한 페이지: 질문 → 답변 · 인용 근거(클릭하면 원문) · 근거 서브그래프(pyvis) · 사용한 경로(Cypher면 쿼리 표시). 밀리면 CLI로 대체(자르는 순서 1).

## D2. 오프라인 번들 · 증거 (D2)

Docker는 internal 네트워크에만 붙은 컨테이너의 포트를 호스트에 열지 않으므로, **`ui`는 internal 네트워크와 일반 bridge 네트워크에 함께 붙여** 호스트 포트를 연다. 그래서 `ui`에는 외부 경로가 남고, 이 부분은 "호스트 인터넷을 끈 상태에서 동작" 증거로 보완한다. 모델은 호스트 볼륨에서 마운트
- 번들: `docker save`로 이미지 tar(의존성은 이미지 안에 설치돼 있음), 모델 · Neo4j 플러그인, 설치 순서 문서. Windows용 wheel은 Linux 컨테이너에서 못 쓰므로 `pip download` 단계는 넣지 않는다
- 증거: 호스트 인터넷을 끈 상태에서 번들로 기동 → 데모 질문 실행 캡처, 컨테이너 안 외부 접속 실패 로그, `docker network inspect` 출력

**9차 외부 검토 반영 (2026-10-26)**

**10차 외부 검토 반영 (2026-10-26)**
