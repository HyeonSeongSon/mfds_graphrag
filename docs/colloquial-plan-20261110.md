# 일반 사용자 입력(구어체) 처리 · 평가 설계안 (2026-11-10)

**상태: 결정 완료(사용자, 2026-11-10).** 3절 갈래 4개 모두 권고안을 채택했다(공문서 행과 나란히, 다른 벤더 API + 검수, 공공 DUR 성분 정보 사전, 거절 세트 포함). 규칙 원문은 `eval/PREREG.md` 4-2-1, 일정은 `docs/PLAN.md` "새 4주 일정"(마감 12-11, 11-10에 재개를 11-16으로 미룸)이다. 일정 연장은 사용자가 허용했다.

**11-10 다른 세션 검토 반영:** 아래 본문은 PREREG 4-2-1과 맞췄다. 그래도 다른 곳이 있으면 **PREREG가 기준**이다. 검토로 바뀐 점은 주장 행 사전 고정(2주차 D4 저녁 동결 전), 사전을 출제에 쓰지 않고 test 생성 전에 고정, 고정 재시도 프롬프트, 법령명 가림 입력과의 짝 비교, 로컬 4B 정규화, 2단계 검수다.

## 1. 문제

데모와 학습은 일반 사용자를 전제로 하는데, 평가는 공문서 문장만 잰다.

| 어디에 | 지금 |
|---|---|
| 데모 (PLAN 709행) | 소비자 질문 2개를 먼저 보여 줌(병용금기, 건강기능식품 표시 · 광고) |
| 어댑터 B 학습 (PLAN 574 · 663행) | 소비자 말투 · 약칭 · 오타 바꿔 쓰기 포함 |
| 평가셋 (PREREG) | 처분 위반 내용 · 판결요지 · 템플릿 문장뿐. 구어체 0 |

시스템 쪽에도 빈틈이 하나 있다.

- **성분 이름이 영문뿐이다.** DUR 고시 별표의 성분명이 영문이라 `Ingredient.name` · `aliases`도 영문이다(`schema.yaml` 64 · 98행).
- 소비자는 "와파린이랑 아스피린 같이 먹어도 돼?"처럼 한글로 묻는다. 지금은 모델이 이 이름을 영문으로 옮겨 맞혀야만 찾을 수 있다.

## 2. 해결 방향

평가와 시스템을 함께 고친다. 평가만 늘리면 낮은 점수를 확인하는 데서 끝나고, 시스템만 고치면 고쳤다는 증거가 없다.

### 2-1. 평가: 구어체 평가 세트 (사전 등록)

- **대상**
  - T1 · T3: test 400 전부, dev 60 전부
  - Text2Cypher: test 450 전부, dev 70 전부
  - 거절 세트: test 150, dev 20
  - 원래 문항마다 구어체 짝을 하나씩 만든다.
- **정답:** 원래 문항 정답을 그대로 쓴다. 원래 v1 파일은 건드리지 않고, `eval/evalset/v1/colloquial/`에 둔다(문항 ID는 원래 ID + `:c`).
- **바꿔 쓰기 입력:** T1 · T3는 "조문 + 법령명 가림" 입력(가림 표시는 일상어로 바꾸거나 빼게 함), Text2Cypher · 거절은 v1 문장 그대로. 가림 전 원문을 주면 모델이 조문 번호를 보고 그 조문 내용을 풀어 쓴 단서를 남길 수 있다.
- **바꿔 쓰기 규칙**
  - 일반인이 실제로 쓸 말투로 쓴다(행정 용어 → 일상어, 군더더기 허용).
  - **T1 · T3에는 조문 번호와 법령명을 넣지 않는다.** 일반인은 대개 법령명을 모르므로 T1 · T3 구어체 행은 "법령명 없음" 조건이 된다. Text2Cypher · 거절 세트는 법령 · 조문이 슬롯이라 남긴다. 그래서 J3의 법령명 단서 문제도 이 세트로 함께 잰다.
  - Text2Cypher는 슬롯(성분 · 조문 · 업종 등)의 뜻을 보존한다. 성분은 **한글 이름으로 바꿔도 된다.** 이것이 소비자 질문의 핵심이다. 바꿔 쓰는 모델에게 성분 한글명 사전은 보여 주지 않는다(출제가 사전에 맞춰지면 정규화 행이 부풀려짐).
  - 사실을 더하거나 빼지 않는다.
  - 처분 라벨 · 업종 · 처분 유형 값 · 판례 법원명 · 사건번호는 글자 그대로 둔다(그래프 속성 값과 같은 문자열이어야 쿼리가 맞음). 자동 검사는 공백만 정규화한 부분 문자열.
- **자동 검사**
  - T1 · T3: 가린 뒤 남은 조문 참조 0, 법령명 0(기존 확인 규칙)
  - Text2Cypher · 거절: 성분이 아닌 슬롯은 이름 · 번호 · 값이 문장에 있음. 성분은 영문 · `aliases` · 고정한 사전의 한글명이면 자동 통과, 아니면 "사전 밖 이름"으로 표시해 사람이 전부 확인. 슬롯이 깨졌으면 재시도 프롬프트로 한 번 더, 그래도 실패하면 빼고 수를 보고. 표본 검수는 이 처리 뒤 세트로. 사전 안 · 밖 비율 보고
  - 공통: 길이 범위, 원문(바꿔 쓰기 입력)과 같은 문장 금지, 가림 표시 없음
  - 문항당 생성은 최대 2회(첫 생성 + 재시도). 재시도 문장이 어느 검사 · 확인에서든 실패하면 뺀다.
  - 검사를 통과하지 못한 문장은 고정 재시도 프롬프트(실패 이유를 붙인 문안, 해시 기록)로 한 번 더 생성하고, 두 번 실패하면 그 문항을 구어체 세트에서 뺀다. 뺀 수는 보고한다.
- **바꿔 쓰는 모델:** 평가에도 학습에도 쓰지 않는 모델로 한다(아래 3절 결정 2).
  - 이 조건은 주 벤더 선택 · 벤더 약관 확인(둘 다 기한 11-17, 11-11~13 권장)에 묶여 있다. 로컬 대안 후보 모델 · 라이선스도 같은 기한에 정한다.
  - **키가 11-18까지 없으면:** 다른 벤더의 오픈 가중치 모델을 로컬에서 temperature 0으로 쓴다(Qwen 제외, 모델 · 파일 해시 기록, GPU 약 4~10시간). 한 번 정하면 키가 와도 바꾸지 않는다.
  - 어댑터 B 학습용 바꿔 쓰기와 같은 모델을 쓰면, 학습 문체와 평가 문체가 같아져 어댑터가 부풀려진다.
  - 답변 API 천장과 같은 모델을 쓰면 API가 유리하다.
- **프롬프트는 dev로만 다듬는다.** test에는 확정 프롬프트로 한 번만 돌린다. 프롬프트 · 모델 · 버전 · 설정 해시를 AMENDMENTS에 기록한다.
- **사람 검수(사용자)**
  - T1 · T3 · Text2Cypher 묶음에서 `SEED` 순서로 50개씩(Text2Cypher는 T2 17 · T4 17 · T6 4 · 거절 12), 약 3시간
  - 확인할 것: 같은 정답이 여전히 맞는가, 일반인 말투인가
  - 라벨 검수와 같은 2단계(오류 1건 이상이면 50개 더, 100개로 계산)와 Wilson 상한 규칙. 5%를 넘으면 오류 패턴을 고치는 규칙을 AMENDMENTS에 남기고, 그 묶음을 다시 생성해 같은 2단계로 다시 검수한다.
- **누수 방지**
  - 구어체 문장은 `exclusion_ids.json`과 별도인 `eval/evalset/v1/colloquial/strings.json`에 둔다(v1 제외 목록은 그대로).
  - 학습 데이터 생성기는 이 목록과 근접 중복(슬롯 가림 뒤 Jaccard 0.8)이면 버린다.
- **보고:** 공문서 행과 구어체 행을 나란히 둔다.
  - 검색: 방식별 hit@5. 유형별 McNemar는 두 행 모두 같은 규칙으로 한다.
  - **말투 강건성:** 방식마다 공문서 대 구어체 hit@5 짝 비교(McNemar). T1 · T3는 공문서 쪽을 "조문 + 법령명 가림" 입력으로 해 법령명 효과를 뺀다
  - Text2Cypher: 주 지표를 두 행으로. 어댑터 B 채택 판정은 공문서 행 기준을 그대로 두고, 구어체 행은 함께 보고한다.
  - **주장 행은 2주차 D4 저녁 동결 전에 dev로 정한 설정의 입력(정규화를 켜면 정규화 입력)으로 미리 정하고, 다른 입력 행은 보조다. "일반 사용자 질문에서 낫다"는 그 행의 유형별 McNemar로만 주장한다.** T1 + T3 합산은 "합산 보조 분석에서 차이 검출"로만 적는다.
  - 답변: 공문서 행과 같은 850(T2 음성 · T6 포함) + 거절 150. 음성 판정이 없으면 늘 "병용금기"라고 답하는 모델도 좋아 보인다. 답변 프롬프트에는 원래 구어체 질문을 넣고, 서브그래프만 주장 행 입력으로 만든다(정규화 문장을 넣으면 답변이 쉬워짐).
  - 시간이 모자라면 양자화 구어체 행을 운영점 한 구성으로 줄이고 어댑터 B 구어체 보조 입력 행을 빼는 것만 허용한다(돌리기 전에 정하고 "줄임"으로 기록, PREREG 4-5).
- **크기:** 원래 문항과 같은 수라 해상도도 같다(유형별 약 10%p, T1 + T3 합산 약 6~7%p, Text2Cypher 450).

### 2-2. 시스템: 일반 사용자 입력 처리

1. **성분 한글명 사전**
   - 공공 DUR 성분 정보(공공데이터포털, 성분 한글명 · 영문명)에서 한글명을 받아, 고시 성분 uid에 붙인다.
   - 서비스 이름과 필드는 받기 전에 확인한다. 공공데이터포털 키(`DATA_GO_KR_KEY`)는 지금 비어 있어 사용자가 활용신청을 해야 한다.
   - 잠금 대상(`schema.yaml` · `ingredients.py`)을 바꾸지 않도록, 사전은 **파이프라인 전처리 파일**로 둔다(`data/aliases/ingredient_ko.tsv`, 출처 · 해시 기록).
   - 정답 uid는 바뀌지 않는다.
   - **고정 시점:** 공공 데이터에서 고정 스크립트로만 만들고, Text2Cypher 구어체 test를 생성하기 전에 해시를 기록한다. test 문장에서 본 이름은 더하지 않는다(dev는 고정 전까지 허용 · 기록).
   - **기한(11-20)을 넘기면:** 같은 스크립트로 영문 이름 · `aliases`만 든 사전을 고정하고 생성한다. 한글 성분명 문항은 모두 사전 밖 이름으로 사람이 확인한다(최악 test 약 260 + dev 약 40, 약 2.5시간). 고정 뒤 받은 자료는 평가 수치에 쓰지 않고 한계로 적는다.
2. **질의 정규화 단계(파이프라인)**
   - 구어체 질문을 검색 전에 행정 용어로 고쳐 쓰는 단계를 둔다(예: "날짜 지난 재료" → "소비기한 경과 원료"). 모델은 로컬 4B 베이스(질의 경로 분류와 같은 모델, thinking 끔)이고 API는 쓰지 않는다(온프레미스).
   - 성분 한글명은 사전으로 영문 uid에 맞춘다.
   - 이 단계를 켤지는 **구어체 dev로 정하고**, 2주차 D4 저녁 동결(Text2Cypher 구어체 test가 그날 밤 먼저 돔) 때 프롬프트 · 사전 해시를 기록한다.
   - 검색 방식 비교(핵심 성과 2)는 정규화 없는 순수 입력과 정규화한 입력을 모두 보고한다. 방식 간 공정성을 위해 세 방식에 같은 정규화 결과를 넣는다.
3. **어댑터 B:** 학습 데이터에 이미 소비자 말투 바꿔 쓰기가 있다. 성분 한글명 슬롯 표기를 바꿔 쓰기 규칙에 더한다(사전이 있을 때).

## 3. 사용자 결정이 필요한 갈래

1. **구어체 세트의 지위:** 공문서 행과 나란히 사전 등록(권고) / 보조로만
2. **바꿔 쓰는 모델:** 평가 · 학습에 안 쓰는 다른 벤더 API + 사람 검수(권고) / 로컬 8B(평가 대상이라 편향) / 사람이 직접(1,200문장이라 비현실적)
3. **성분 한글명:** 공공 DUR 성분 정보로 사전 수집(권고, 키 신청 필요) / 사람이 자주 쓰는 성분만 작성 / 사전 없이 모델 번역에 맡기고 재기만 함
4. **범위:** T1 · T3 + Text2Cypher + 거절 세트 전부(권고) / 거절 세트 제외
